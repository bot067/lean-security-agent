## 4. ЗАФИКСИРОВАННЫЕ ОТКАЗЫ И ИХ ПРИЧИНЫ (дифференциальный ряд)

### Отказ A — Коллапс производительности на 12B (Saiga, 02.08.2026) 🔴
- Saiga 12B Q4_K_M: **1.0–1.8 ток/сек** (цель ≥5–7 ❌), VRAM **7699/8192 МБ**, ответ на промпт 5k — **23–33 с**.

### Отказ B — Переполнение контекста (сентябрь 2026) 🔴
```
send_error: task id = 0, error: request (15745 tokens) exceeds the
available context size (10496 tokens), try increasing it
```
- Этиология: агентский цикл накопил 15 745 токенов при доступных 10 496. Следствие: жёсткий сбой запроса **без деградации** — задача теряется целиком.

### Отказ C — Падение загрузки модели (OOM, 10.09.2026) 🔴
```

- Этиология: движок не выделил память при старте (конкуренция за VRAM между инстансами). Нужна выгрузка + повторный запуск.

### Отказ D — «Пустые ответы» reasoning-моделей 🟠
Из прод-замеров: *«Qwen3 пустой ответ — без `think=False` не отвечает»*. Этиология: вся квота вывода уходит в блок `thinking`.

### Отказ E — Битый JSON в ответе агента 🟠
Реальные строки из логов Lean Security Agent — модель заворачивает JSON в markdown-забор:
```

```
Плюс следы тегов `thinking` внутри `content`. Прямое следствие — падение парсера агента.

### Отказ F — Сетевые блокировки провайдеров в РФ 🔴

## 6. КЕЙС-ИССЛЕДОВАНИЕ: LEAN SECURITY AGENT (реальная архитектура)

**Репозиторий:** [github.com/bot067/lean-security-agent](https://github.com/bot067/lean-security-agent) — public, Python 3.11+, Docker, Zero Trust.

Архитектура проекта — прямое подтверждение выводов отчёта: локальная LLM выступает **только планировщиком** (выдаёт строгий JSON-запрос инструмента), исполнение идёт в изолированном Docker-контейнере, а **Smart Pruner** обрезает вывод инструментов перед возвратом модели.

| Элемент архитектуры | Эмпирическое подтверждение | Вердикт |
|---|---|---|
| LLM-планировщик на локальной модели `:1234` | 57–60 ток/с, ctx 4096, 0 ₽ | ✅ Жизнеспособно |
| JSON-контракт инструментов | Требует `json_schema` (иначе 400 / markdown-забор) | ⚠️ Обязательно `json_schema` |
| **Smart Pruner** (обрезка вывода) | Логи: `15745 > 10496` → сбой без прунинга | ✅ Архитектурно необходимо |
| Zero Trust / Docker-изоляция | — (вне периметра замера GPU) | ✅ |
| reasoning off у планировщика | Логи: `thinking` в `content` ломает парсер | ⚠️ Обязателен `think=False` |

**Вывод по кейсу:** архитектура Lean Security Agent **физически состоятельна** на RTX 5060 8GB, но её устойчивость критически зависит от трёх деталей, доказанных логами: (1) `json_schema` вместо свободного JSON, (2) обязательный Smart Pruner против переполнения контекста, (3) жёсткое выключение reasoning у планировщика.
