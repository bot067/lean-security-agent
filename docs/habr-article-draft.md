## Проблема: экосистема не универсальна

Запуск агента на реальных целях выявил фундаментальную проблему: **SPA-экосистема фрагментирована**. Angular 2+ и AngularJS (1.x) — это разные фреймворки с разными API, разными механизмами безопасности и, как следствие, разными векторами атак.

Один и тот же паттерн выглядит по-разному в зависимости от версии фреймворка:

| Вектор | Angular 2+ | AngularJS (1.x) |
|--------|------------|-----------------|
| DOM XSS | `bypassSecurityTrustHtml` | `$sce.trustAsHtml` |
| Template Injection | `Compiler.compileModule` | `$compileProvider` |
| Client-side Storage | `localStorage` | `$cookies` |

Сделать универсальный набор правил для всех SPA — значит получить высокий false positive rate и упустить специфичные уязвимости. Нужна система, которая определяет фреймворк цели и применяет релевантные правила.

---

## Решение: навыки и автоопределение

Архитектура строится вокруг двух механизмов: **автоопределение фреймворка** и **динамическая загрузка навыков**.

### Как это работает

Агент получает HTML-ответ от целевого приложения, анализирует характерные признаки в DOM и загружает соответствующий набор правил статического анализа и пейлоадов для динамической проверки.

```
1. curl http://target:3000/ → HTML
2. Анализ body: polyfills.js + main.js → нет ng-version
3. Вывод: AngularJS (legacy)
4. Загрузка навыка: angularjs-security-assessment
5. Статика: rg --json -g *.js -g *.ts по 15 правилам
6. Динамика: curl POST с XSS-пейлоадами
7. Агрегация findings в формат file:line | severity | rule_id | snippet
```

Автоопределение работает по устойчивым сигнатурам в DOM:

- `ng-version` или бандлы `main-es`, `polyfills-es` → Angular 2+
- `polyfills.js` + `main.js` без `ng-version` → AngularJS
- `id="root"` или `__REACT_DEVTOOLS_GLOBAL_HOOK__` → React
- `data-v-` или `__VUE_DEVTOOLS_GLOBAL_HOOK__` → Vue

Каждый навык — это JSON-файлы с правилами для ripgrep и пейлоадами для curl. Добавление нового фреймворка (React, Vue, Svelte) не требует правки оркестратора: достаточно создать три JSON-файла по шаблону и зарегистрировать в конфигурации.

### Разделение Angular-навыка

В процессе работы выяснилось, что Juice Shop написан на AngularJS 1.x, а не Angular 2+. Это потребовало разделения навыка на два:

- **Angular 2+** (20 правил): `bypassSecurityTrust*`, `[innerHTML]`, `Compiler.compileModule`, `localStorage.setItem`
- **AngularJS 1.x** (15 правил): `$sce.trustAsHtml`, `ng-bind-html`, `$compile`, `$cookies.put`

Каждый навык загружается только после автоопределения фреймворка. Это исключило ложные срабатывания и повысило точность детекции.

## Кейс: пентест OWASP Juice Shop

OWASP Juice Shop — уязвимое веб-приложение для тестирования навыков пентеста. Оно написано на AngularJS, содержит десятки умышленных уязвимостей и является стандартным полигоном в сообществе security-инженеров.

### Окружение эксперимента

| Параметр | Значение |
|----------|----------|
| GPU | RTX 5060 (8 GB VRAM) |
| RAM | 16 GB |
| Модель | Qwen 2.5 9B (Q4_K_M, ~5 GB) |
| Контекст | 4096 токенов |
| Цель | Juice Shop на AngularJS |

### Что произошло

Оркестратор запустил сканирование, выполнил curl к целевой странице, проанализировал HTML-код и обнаружил `polyfills.js` и `main.js` при отсутствии `ng-version`. На основании этих сигнатур агент загрузил навык `angularjs-security-assessment` — 15 правил для ripgrep и 30 пейлоадов для curl.

**Статический анализ** (ripgrep, 1.3 сек): прогон 15 правил по тестовому исходному коду выявил 23 уязвимости.

**Динамический анализ** (curl, 0.5 сек): отправка XSS-пейлоадов, проверка заголовков HTTP, тест Prototype Pollution.

### Результаты

| Метрика | Значение |
|---------|----------|
| Время выполнения | 2.2 сек (1.3 static + 0.5 dynamic) |
| VRAM delta | 0 MB |
| Найдено уязвимостей | 23 (5 CRITICAL, 14 HIGH, 4 MEDIUM) |
| Детектор петель | 0 срабатываний |
| Smart Pruner | 0 срабатываний |

**Критические находки (5):**
- `$sce.trustAsHtml` — отключение контекстного экранирования HTML
- `$sce.trustAsJs` — выполнение JavaScript без проверки
- `$compile(userInput)` — динамическая компиляция шаблона с невалидированным вводом
- `$sce.trustAsResourceUrl` — доверие к внешним ресурсам

**Высокий риск (14):**
- `ng-bind-html` без `$sanitize` — вставка несанитизированного HTML
- `localStorage.setItem` для токенов — доступность при XSS
- `angular.extend` с пользовательским вводом — Prototype Pollution
- `$routeParams` без валидации — Open Redirect

**Средний риск (4):**
- `$cookies.put` без HttpOnly
- `orderBy` с пользовательским вводом — legacy RCE (CVE-2015-5255)

**Динамические проверки:** три XSS-пейлоада не отразились в ответе (Juice Shop не рефлектит в POST /). Выявлено отсутствие Content-Security-Policy. Prototype Pollution подтвержден HTTP 200.

### Архитектурный смысл метрик

Время 2.2 секунды и нулевой прирост VRAM — это не случайность, а следствие Planner-Executor Separation. Тяжелая LLM (5 GB VRAM) не участвует в парсинге вывода ripgrep и не ждет ответа от curl. Оркестратор выполняет инструменты напрямую через `docker exec security-agent` и передает модели только структурированный, уже усеченный результат. В данном случае Smart Pruner даже не потребовался — вывод уложился в 100 строк. Это означает, что 8 GB VRAM расходуются исключительно на инференс модели, а не на утилитарные задачи.

## Сравнение с альтернативами

Для security-задач приватность данных — критическое требование. Конфиденциальные кодовые базы и отчеты об уязвимостях не должны покидать хост.

### Локально vs Облако

Параметр | Lean Agent | GPT-4
---|---|---
Цена | $0 | $10–30 / 1M токенов
Приватность | Данные не покидают хост | Данные уходят в облако
Скорость | 30–50 ток/сек | 50–100 ток/сек
Качество findings | Хорошее | Отличное

Для внутренних систем, где NDA и конфиденциальность первичны, локальный агент на потребительском железе — оптимальный выбор.

### 9B vs 70B

Модель | VRAM | Скорость | Качество
---|---|---
Qwen 2.5 9B (Q4) | 5 GB | 30–50 ток/сек | Хорошее
Llama 3 70B (Q4) | 40 GB | 5–10 ток/сек | Отличное

На RTX 5060 с 8 GB VRAM 70B не поместится. 9B с квантованием Q4 — максимум, обеспечивающий приемлемую скорость при достаточном качестве для задач автоматизированной оценки уязвимостей.
