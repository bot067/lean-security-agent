Локальный автономный агент для оценки защищенности веб-приложений. Система обеспечивает выполнение задач искусственного интеллекта в строго изолированной Docker-среде, без доступа к глобальной сети или хост-машине.

## Обзор

Lean Security Agent преобразует генеративные возможности локальных языковых моделей (LLM) в детерминированный, безопасный конвейер для поиска уязвимостей. Архитектура построена по принципу нулевого доверия (Zero Trust), где модель выступает исключительно в роли планировщика, а все исполнительные действия проходят через многоуровневую систему валидации и изоляции.

## Принцип работы

1. **Инициация:** Оператор формулирует задачу (например, "обнаружить SQL-инъекции на 172.20.0.10:3000").
2. **Планирование:** Оркестратор передает запрос локальной LLM через OpenAI-совместимый API.
3. **Формирование команды:** Модель возвращает структурированный JSON-запрос на выполнение инструмента.
4. **Валидация:** Оркестратор проверяет команду по строгому белому списку и блокирует опасные паттерны.
5. **Изолированное выполнение:** Команда запускается внутри ограниченного Docker-контейнера.
6. **Управление контекстом:** Модуль Smart Pruner обрезает избыточный вывод, возвращая модели только релевантные данные для принятия следующего решения.

## Архитектура системы

```text
Локальная LLM (127.0.0.1:1234)
      |
      v OpenAI-compatible API
Оркестратор (Python)
      |
      v docker exec (строго валидированный argv)
Контейнер security-agent (172.20.0.20)
      |
      v HTTP-трафик разрешен только к цели
Целевое приложение (172.20.0.10:3000)
```

## Безопасность и изоляция

Система реализует защиту на нескольких уровнях (Defense in Depth):

* **Минимальные привилегии:** Контейнер работает от имени пользователя `nobody`.
* **Неизменяемая среда:** Корневая файловая система монтируется в режиме Read-Only.
* **Ограничение ресурсов:** жесткие лимиты на 2 GB оперативной памяти и 2 ядра CPU.
* **Сетевая изоляция:** Использование внутренней сети Docker (`--internal`), полностью блокирующей доступ в интернет и к хост-машине.
* **Контроль исполнения:** Белый список разрешенных утилит и регулярные выражения для блокировки деструктивных паттернов (например, `rm -rf`, `eval`, конвейеры в shell).
* **Стабильность сессии:** Встроенный детектор зацикливания автоматически останавливает процесс при трехкратном повторении идентичной команды.
* **Экономия контекста:** Алгоритм Smart Pruner сохраняет только первые 50 и последние 50 строк вывода, предотвращая переполнение контекстного окна LLM.

## Системные требования

* **Язык:** Python 3.11 или выше
* **Контейнеризация:** Docker и Docker Compose
* **Аппаратное обеспечение:** GPU с 8+ GB видеопамяти (рекомендуется RTX 4060/5060 или аналог)
* **Инференс:** LM Studio или Bionic Studio с моделью Qwen 2.5 7B/9B (квантование Q4_K_M)

## Быстрый старт

Клонирование репозитория и установка зависимостей:

```bash
git clone https://github.com/bot067/lean-security-agent.git
cd lean-security-agent
pip install -r requirements.txt
```

Подготовка окружения:

1. Запустите LM Studio, загрузите модель и убедитесь, что локальный сервер API доступен по адресу `127.0.0.1:1234`.
2. Разверните тестовую среду и контейнер агента:

```bash
docker compose -f config/docker-compose.yml up -d
```

Запуск агента:

```bash
python src/orchestrator/main.py --task "probe 172.20.0.10:3000"
```

## Тестирование

Проект включает комплексный набор тестов для проверки надежности и безопасности:

```bash
pytest tests/unit/          # Модульное тестирование парсеров и валидаторов
pytest tests/integration/   # Проверка взаимодействия оркестратора и Docker
pytest tests/security/      # Red Team сценарии: попытки инъекций и обхода политик
```
